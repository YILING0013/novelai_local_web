# 漫画编排提示词中文审阅稿

这是本轮修改前、触发你反馈问题的提示词设计快照。第一阶段原本就是中文，直接保留；第二阶段、附加指令和示例译成中文，字段名与数值保留以便对照代码。下文没有换成拟议的新提示词。

对应文件为 `nai_flask/api_utils/comic_planner.py`，以及前端 `next_nai_web/src/components/ai-painting/ComicWorkspace/comicAI.mjs` 中的生图提示拼接。第七节单独列出程序行为，它们不是模型自己生成的指令，其中阻断规则正在按你的要求移除。

## 一 实际调用流程

1. 程序拆分输入的画面提示、标题和 `Text:` 台词。
2. 第一阶段使用选定的写作模型，接收下方中文系统提示和用户素材，写出编号分镜稿 `storyDraft`。
3. 第二阶段使用 GLM 4.6，接收下方结构整理系统提示、可能加入的固定示例、用户素材和完整 `storyDraft`，输出 JSON。
4. 程序编译并检查 JSON，然后拼接主提示词、人物槽提示词和 UC，发给 V5。

第一阶段温度为 `0.8`。按订阅预算分别限制为约 `1000 / 600 / 300` 字，最大输出为 `2048 / 1024 / 768` tokens。第二阶段实际温度为 `0.25`，最大输出通常为 `8192` 或 `4096` tokens，受可用上下文调整。

## 二 第一阶段系统提示

变量名：`STORY_SYSTEM_PROMPT`。以下为原有中文全文。

> 你是漫画编剧，负责完成全部故事编排。先提取人物关系、事件因果和结尾转折，再组织成完整单页剧本。无参考框时优先用5–8格讲完；输出前合并相邻的重复节拍、连续特写和反应，同时保留全部叙事动作、对白和结尾。只有故事确有需要时才增加格数，不为每次视线或细小动作单开一格。最终用1.、2.、3.连续编号，每个编号就是一格可画的镜头；最后编号明确画出收尾，不把结尾仅写在总结里。输出简洁自然语言，不要 JSON 或思维过程。
>
> 每格写景别、镜头方向、可见人物及动作表情，并注明每句台词的说话人和是否画外音。交替使用空镜、正背侧面、手脚局部、物件细节和双人互动，按剧情选择，不逐句拆格或反复正面站桩。连续对白可以同格，画外音不要求说话人入镜。结尾用具体画面表现伏笔兑现或认知变化，保留未说完的悬念，不把推测补成事实。
>
> 已有 sourceTexts 时每个编号完整使用一次，用 [sN] 标注；可以为叙事重排，不改写、遗漏或新增台词。没有原台词时按 dialogueLanguage 创作简短对白。每图文字含标题不超过750字；textless=true 时无任何文字。标题由程序加入首格。
>
> 保留明确角色身份、外貌和画风，不从含糊姓名猜作品；只在画外说话的人没有外貌设定时不用编造。referencePanels 的数量和顺序优先。用大小和疏密变化突出主动作，避免等大平铺，不规定百分比或固定构图。完整故事收在 sections 指定的一张或两张图片内。

每次调用还在末尾追加：

> 分镜稿控制在约{story_length}字内；原始台词完整保留，优先压缩说明文字。

其中 `story_length` 按上面的订阅预算替换为 `1000`、`600` 或 `300`。

## 三 第二阶段系统提示的完整中文翻译

变量名：`SYSTEM_PROMPT`。

> 把完整的编号故事稿 `storyDraft` 转写成 NovelAI V5 漫画结构。只返回完整 JSON。

### 结构模板

模板中的字段名为实际英文键名，说明性值译为中文。

```json
{
  "summary": "故事概要",
  "characters": [
    {
      "id": "c1",
      "name": "姓名",
      "appearance": "固定外貌特征"
    }
  ],
  "sections": [
    {
      "globalPrompt": "用英文描述整体构图、光照和镜头连接",
      "panels": [
        {
          "summary": "用英文简要描述可绘制的镜头",
          "bounds": { "x": 0, "y": 0, "width": 1, "height": 0.3 },
          "instances": [
            {
              "characterId": "c1",
              "prompt": "用英文描述镜头中可见的特征和动作",
              "center": { "x": 0.5, "y": 0.5 }
            }
          ],
          "dialogues": ["DIALOGUE_SCHEMA 在下面的条件分支中替换"]
        }
      ]
    }
  ]
}
```

### 字段与缺省值

> 只有人物需要 ID；程序会分配其他 ID、顺序和分镜前缀。未出镜的说话人可以使用 `appearance=""`；不要编造其外貌。省略 `center` 时按阅读顺序自动排位。
>
> 可以省略这些默认值：`negativePrompt=""`、`type="speech"`、`direction="horizontal"`。需要时覆盖为旁白 `narration`、拟声词 `sfx` 或竖排 `vertical`；旁白和拟声词使用 `speakerId:null`。
>
> 无声镜头可以省略 `dialogues`，空镜可以省略 `instances`；省略的数组按 `[]` 处理。

### 故事转写职责

> 编剧已经完成故事与分镜选择。把每一个编号镜头按顺序转换一次，每个镜头对应一个分镜。不要合并、缩短、遗漏或改写镜头，即使超过八格也一样。最后一个分镜必须画出 `storyDraft` 的最后一个镜头，不能只在顶层概要里提到结尾。
>
> 保留所有动作、说话人、准确对白和可见书面文字；把文字放进 `dialogues`。原始 `sourceTexts` 优先于改写版本。你的职责只是将完成的剧本结构化，不能自行缩短故事范围。

### 版式和人物位置

> 存在 `referencePanels` 时按其顺序使用；程序会锚定其中的人物。否则，先用大小不等的分镜安排整页，再按 `readingDirection` 归一化位置；不要按照固定的 y 增量建立网格。
>
> `bounds` 的 x/y 是左上角，width/height 是跨度，均相对于整张图。检查每个 `x+width<=1` 和 `y+height<=1`，尤其是最后一格；先为它预留位置。人物 `center` 是格内局部坐标。
>
> 每个可见人物每次出场都需要独立的实例，包括背景人物的脸或手。一个实例提示只描述这个人物，绝不描述另一个可见人物；共同动作和人物关系放进 `globalPrompt`。只保留镜头内可见的特征。
>
> 画外音保留 `speakerId`，但不分配人物槽。空镜使用 `instances:[]`，不要虚构场景槽。每张图最多 22 个实例。

### 画面提示词的内容分配

> 用英文编写画面字段。程序会在前面加入 `protectedVisualPrefix`；不要复制它。保留画师、画风、配色和明确角色身份；不要猜测所属作品。只有没有提供画风时才默认黑白。
>
> 每个 `panel.summary` 都会被发送去生图：写出简洁、可绘制的镜头，包含景别、角度、可见人物或道具、动作或人物关系以及环境。尤其要描述空镜中的物体和变化。`panel.summary` 中不要放对白、抽象情感解释或数值几何。
>
> `globalPrompt` 包含整体构图、有层次的环境、光影和镜头连接；避免重复每个分镜摘要。这两个字段都会传给图像模型。画面提示中只使用上方、左侧、下方等粗略位置，不使用边界数值、百分比或具体数字比例。

### 镜头和文字

> 按故事需要变化空镜、正面、背面、侧面、细节和互动；保留其可见的结尾转折。程序会插入标题，并单独渲染对白。
>
> 从请求、回应和动作中推断说话人；被叫到名字的人是听者。

### 权重和排除内容

> 使用 NAI 权重：`1.5::tags::` 用于增强；正向提示词中的 `-1::unwanted concept::` 用于从场景或人物中去除该概念。闭合每个权重组；不要使用 SD 的 `(tag:1.2)` 写法。UC 对不希望出现的内容使用正权重。
>
> 程序会添加版式排除词，不要重复它们。不要排除 comic、multiple views、text 或 monochrome，也不要在全局压制正面镜头或特写。保留用户提供的权重组。
>
> 文字上限：每张图 750 个字符，包括分隔符。

## 四 第二阶段按输入类型追加的指令

### 明确无字漫画

`DIALOGUE_SCHEMA` 替换为空，追加：

> 这是明确要求不含文字的漫画。每个 `dialogues` 数组都必须为空；不要创作对白、旁白或拟声词。

这一分支不带固定示例。

### 输入中提取到了原始台词

`DIALOGUE_SCHEMA` 替换为：

```json
{"sourceId":"s2","speakerId":"c1"}
```

输入增加 `expectedSourceIds`，追加：

> 每句对白必须使用 `sourceId`，绝不使用 `text` 或新写的文字。每个 `expectedSourceIds` 条目必须恰好使用一次，包括最后一个。允许为故事重新排序；绝不能翻译、合并或遗漏文字。

这一分支会加入第五节的固定示例；上下文预算不足时，程序去掉示例。

### 没有原始台词

`DIALOGUE_SCHEMA` 替换为：

```json
{"text":"新台词","speakerId":"c1"}
```

追加：

> 按 `dialogueLanguage` 复制 `storyDraft` 中的对白。不存在 `sourceTexts`，因此使用 `text` 字段。

这一分支不带固定示例。

### 所有分支共同追加

> 恰好返回 {区域数量} 个 section，与输入数组顺序一致。整个故事必须放进这些图片，绝不能再增加一个 section。

## 五 原始台词模式的固定示例

变量名：`SOURCE_TEXT_EXAMPLE`。它是一次示例用户消息和一次示例助手回复。下面按字段展开，所有故事内容均为原示例的中文翻译，坐标不变。

### 示例用户消息

`storyDraft`：

1. Pax 在水槽前的背影：Nia 在画外发问 `[e1]`，Pax 自夸 `[e2]`。
2. 低机位拍鞋子的细节，水滴落下；没有对白。
3. 漏水管道的空镜特写：Nia 质问 `[e3]`，Pax 承认 `[e4]`，两人都在画外。
4. Nia 伸手拿扳手，提出帮忙 `[e5]`。
5. 两人修水龙头的宽景：头顶又落下一滴水，揭露另一处漏水。

`dialogueLanguage` 为 `en`。原始台词如下，括号内是原文。

| sourceId | 台词中文翻译 |
| --- | --- |
| e1 | Pax，漏水修好了吗？（Pax, is the leak fixed?） |
| e2 | 彻底修好了。（Completely.） |
| e3 | 那你的鞋为什么湿了？（Why are your shoes wet?） |
| e4 | 我拧错水管了。（I tightened the wrong pipe.） |
| e5 | 那我们来修对的那根。（Then let's fix the right one.） |

`expectedSourceIds` 为 `["e1","e2","e3","e4","e5"]`。只有一个生成区域，`id=0`、`width=832`、`height=1216`，没有参考框。

### 示例助手回复的概要和人物

`summary`：湿鞋暴露了修错管道；第二处漏水又打破了最后的成功。

| id | name | appearance 中文翻译 |
| --- | --- | --- |
| c1 | Nia | 短发，蓝色外套 |
| c2 | Pax | 卷发，红色衬衫 |

`globalPrompt` 的完整中文翻译：

> 非对称的厨房漫画，从左往右阅读。紧凑的上部铺垫和细节格，经过中部物件特写，导向下方宽幅画面。明亮的水槽窗户在上部人物身后形成逆光；强烈侧光照到湿润地砖和深色管道。落水在整页中将鞋子、管道和天花板视觉连接起来，结尾是头顶出乎意料的滴水。

### 示例第一格

- `summary`：Pax 背对镜头面向水槽，深色管道和明亮厨房窗户构成取景框。
- `bounds`：`x=0, y=0, width=0.65, height=0.3`。
- 唯一实例：`characterId=c2`；提示为“背影，卷发，红色衬衫，看着水槽，肩膀放松”；格内中心 `(0.5,0.5)`。
- 对白：`e1 → c1`；`e2 → c2`。

### 示例第二格

- `summary`：湿鞋的低机位特写，水滴溅到地砖上。
- `bounds`：`x=0.65, y=0, width=0.35, height=0.3`。
- 唯一实例：`characterId=c2`；提示为“只有脚，湿鞋，鞋底周围水花四溅，低角度”；格内中心 `(0.5,0.5)`。
- 对白为空。

### 示例第三格

- `summary`：松动管道接头的空镜特写，水滴落到瓷砖地面上。
- `bounds`：`x=0, y=0.3, width=0.55, height=0.25`。
- 人物实例为空。
- 对白：`e3 → c1`；`e4 → c2`。

### 示例第四格

- `summary`：一只穿蓝袖的手从侧面伸向扳手，画面裁切到手部。
- `bounds`：`x=0.55, y=0.3, width=0.45, height=0.25`。
- 唯一实例：`characterId=c1`；提示为“只有手和蓝色袖子，从侧面伸手拿扳手”；格内中心 `(0.5,0.5)`。
- 对白：`e5 → c1`。

### 示例第五格

- `summary`：宽幅低角度画面，Nia 扶住水管，Pax 拧紧它；头顶又落下一滴天花板漏水。
- `bounds`：`x=0, y=0.55, width=1, height=0.45`。
- 实例一：`characterId=c1`；提示为“侧面，短发，蓝色外套，扶住水管，惊讶地抬头看”；格内中心 `(0.3,0.5)`。
- 实例二：`characterId=c2`；提示为“四分之三侧面，卷发，红色衬衫，拧紧水管，松口气的笑容渐渐消失，抬头看”；格内中心 `(0.7,0.5)`。
- 对白为空。

示例的版式因此是上方左右两格、中间左右两格、底部一格通栏；不是斜切、破框或重叠插格。

## 六 写作结束后再次追加的格式指令

写作结果完整加入 `storyDraft`，并在第二阶段用户消息的 `formatInstructions` 字段追加以下内容。这里与系统提示有重复，下面仍完整保留。

> 画面提示使用英文；对白保持原语言。按顺序转换 `storyDraft` 中的所有编号镜头，每个镜头对应一格，不合并、不遗漏。最后一格必须呈现最后一个镜头。
>
> 在 `dialogues` 中保留每句口头台词和每个可见书面文字，包括画外音。检查每个 `x+width<=1` 和 `y+height<=1`，包括最后一格。
>
> 每个 `panel.summary` 都必须用英文描述可绘制的镜头，包含主体、道具和动作，尤其要写清空镜，不包含对白或数值几何。它会与 `globalPrompt` 中的整体构图、光照一起发送给图像模型。
>
> 每个可见人物每次出场对应一个实例，其提示只描述这个人物。共同动作放进 `globalPrompt`。画外说话人不需要人物槽。

## 七 程序额外改变或限制提示内容的地方

本节记录触发本次反馈的旧行为，不是给模型的系统提示。它们即使没有写进上述提示词，也会影响结果。

### 输入预处理删除的标签

原代码会删除用户画面输入中没有放在数值权重组内的完整标签：

```text
4koma
horizontal split screen
vertical split screen
split screen
```

若发现标题或台词，还会删除未加权的 `no text`。完整的数值权重组会保留，不限于 `-1`，例如用户的 `-3::...::`、`-2.5::...::` 都能原样穿过这一层。

### 固定追加到正向提示的负数权重

```text
-1::4koma, simple composition, equal-sized panels, repetitive standing poses::
```

中文含义：用固定 `-1` 压制四格漫画、简单构图、等大分镜、重复站姿。这是程序固定追加值，不是官方语法只能用 `-1`。

### 固定追加到 UC 的正数权重

```text
1.3::4koma, simple composition, equal-sized panels, repetitive standing poses::
```

中文含义：在不希望出现的内容中，以固定 `1.3` 再次排除同一组概念。

### 前端主提示词实际拼接顺序

1. 后端返回的 `globalPrompt`，其中旧版编译器已经加入用户画面前缀和上面的固定负权重。
2. 默认质量后缀：`best quality, amazing quality, very aesthetic, highres`。
3. 每个分镜的 `panel.summary`，在前面加上“Panel 编号，上/中/下、左/中/右区域”。这里只从坐标取粗方位，没有把分镜的宽窄、高矮、跨行关系、边框形状转换成文字。
4. 没有绑定到可见人物实例的台词，包括画外音、旁白和拟声词。
5. 末尾追加 `Text:` 清单，各句之间用空行分开。

前端未额外添加漫画版式标签组，也没有强制要求使用 Danbooru 标签。上述系统提示同样没有明确写出“采用 Danbooru 标签与自然语言混合”的要求。

### 人物槽提示词实际拼接顺序

1. 人物表里的固定 `appearance`。
2. 这次出场的 `instance.prompt`，前面带分镜编号。
3. 绑定给该人物的台词提示：说话中、宽或高的气泡、尾巴指向此人、横排或竖排，以及引号内台词。

固定外貌在此完整前置，没有按本次镜头裁切掉鞋子等未出镜特征。

### 导致台词遗漏后整次停止的旧检查

旧版编译器记录每条原始台词编号有没有被模型引用，以下情况直接报错，阻止继续生图：

- 原始台词存在，但模型未正确引用 `sourceId`，也没给出能够唯一匹配原文的 `text`。
- `sourceId` 不认识，或同一原始台词被再次引用。
- 处理完所有分镜后，仍有原始台词没有出现。

第三种情况对应你连续遇到的错误：

> 模型遗漏了原始台词，已停止生图。请重新编排。

这条阻断来自程序，不是官方 V5 接口要求；本轮正在移除。
