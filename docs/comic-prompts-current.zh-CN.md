# 当前漫画编排提示词与生图拼接

记录日期：2026-10-19。本文件对应当前代码修订，用于审阅实际发送给模型的提示与程序行为；**本轮提示词修订尚未完成真实生图验收**，不代表已验证版式、剧情或跨页一致性达到预期。

提示全文从 [comic_planner.py](../nai_flask/api_utils/comic_planner.py) 的字符串常量提取，保留原文与换行。前端拼接对应 [comicAI.mjs](../next_nai_web/src/components/ai-painting/ComicWorkspace/comicAI.mjs)。修改前的审阅快照另见 [comic-prompts-before-revision.zh-CN.md](comic-prompts-before-revision.zh-CN.md)，该文件保持原样。

## 一、实际调用流程与参数

1. 程序接收剧情或原生图片提示词。原生提示词会拆出画面提示、`comic title` 标题和 `Text:` 台词；画面部分作为 `protectedVisualPrefix` 保留，标题由程序加入第一张图的首格。
2. 第一阶段使用选定写作模型，把用户素材编为 `storyDraft`。系统消息就是下方 `STORY_SYSTEM_PROMPT` 全文，没有额外的固定字数指令。
3. 第二阶段固定使用 `glm-4-6`，接收 `SYSTEM_PROMPT`、对应输入分支的追加指令、用户素材、完整 `storyDraft` 和 `formatInstructions`，输出 JSON。当前没有 few-shot 示例消息。
4. 程序编译已有分镜、人物实例和台词，整理成前端可用字段；前端再拼接整页提示、各格镜头、人物槽和文字，交给现有 V5 生图流程。

| 阶段 | 实际模型 | 温度 | 最大输出 tokens |
| --- | --- | --- | --- |
| 分镜写作 | 用户选择 `glm-4-6` 或 `xialong-v1`；有效 Opus 默认 Xialong，其余默认 GLM | `0.8` | 订阅 `tier >= 3` 为 `2048`；`tier == 2` 为 `1024`；其余为 `768` |
| JSON 整理 | 固定 `glm-4-6` | `0.45` | 有效 Opus 为 `8192`；其余为 `4096` |

两阶段均使用 `stream=true`、`enable_thinking=false`，各请求一次。Xialong 仍要求有效 Opus 订阅。`prepare_comic_request` 中的 `temperature=0.65` 是初始请求值，实际 JSON 请求前会覆盖为 `0.45`。

当前不再用 UTF-8 字节数估算 token 并拦截中文素材，也不再追加约 1000 / 600 / 300 字的分镜稿限制。第一阶段原文完整传入第二阶段，真实上下文限制交给上游；上表中的输出 token 上限仍然生效。

## 二、第一阶段系统提示全文

变量名：`STORY_SYSTEM_PROMPT`。

```text
你是漫画编剧兼分镜师。把用户素材改编为有起因、行动、反应和收尾的漫画，结尾用看得见的动作兑现笑点、反转或感情变化。保留用户明确的人设、画风、角色标签和故事重点。给定台词尽量保留原文与语言，可按叙事重排并用 [sN] 标出引用；没有给台词时创作简短自然的对白。画外音可以跨空镜，不要求说话人出现在画面里；明确无字时用动作讲故事。
先写一段“整页分镜设计”，再用1.、2.、3.连续编号描述镜头。一般用5–8格，根据故事增减，不把这个数量当规则。整页设计必须说清视觉重心、主格与小格的大小关系、画框如何穿插和阅读动线；可以选择纵向主格、窄条切镜、斜切边框、重叠插格、局部破框或留白，但只用适合本段剧情的手法，不每页套同一布局，不把“复杂”理解为多加几排方格。
每格写出大致位置和画框设计、景别与机位、可见人物或物件、具体动作表情，以及说话人与台词。用远近、俯仰、正背侧面、手脚或物件特写、空镜和双人互动形成节奏，避免连续正面站桩。一个细节可以占小插格，关键行动可撑起主格；镜头中的人与道具关系要能一眼读懂。
不要输出百分比或精确长宽比例；仍然要具体描述宽窄、高矮、跨行、叠压、斜切和边框关系。参考框存在时围绕其布局编排。把完整故事安排在指定的一张或两张图片里。输出分镜设计与剧本，不输出JSON或分析过程。
```

## 三、第二阶段系统提示全文

变量名：`SYSTEM_PROMPT`。其中 `DIALOGUE_SCHEMA` 是运行时替换占位符，三个替换分支见下一节。

```text
你是NovelAI V5漫画提示词作者。把storyDraft中的分镜设计和故事转成下面的JSON，只输出完整JSON。画面提示采用英文Danbooru标签与自然语言混合，台词使用原语言。
结构：
{"summary":"故事概要","characters":[{"id":"c1","name":"姓名","appearance":"稳定的人物外貌和服装标签"}],"sections":[{"globalPrompt":"漫画与画风标签，加具体整页分镜设计","negativePrompt":"本页不希望出现的内容","panels":[{"summary":"景别标签，加这格可画的画框、场景与动作","instances":[{"characterId":"c1","prompt":"本次出场可见的人物特征、机位标签和具体动作"}],"dialogues":[DIALOGUE_SCHEMA]}]}]}
globalPrompt负责真正的整页设计：先写适用的comic、multiple views、画风与环境标签，再具体描述主格的位置和形状、小格围绕它的排列、宽窄高矮对比、插格或破框与边框关系、阅读动线和光影。沿用storyDraft为本故事选择的设计，不要只写“非对称、电影感、大小不等”等空话，也不要自动排成相同的横向条带或1-2-1-2格子。斜切、叠格、纵向大格、无框画面按剧情选用，不把它们组合成每次固定的模板。
panel.summary也会传给生图：用from above、from below、from behind、profile、close-up、wide shot、dutch angle、hand focus等合适标签配合自然语言，写出这格的画框设计、景别、环境、道具和共同动作。空镜直接描述no humans与可见场景。不要把重要镜头只留在summary总览里。人物动作、道具状态与结尾变化应清楚可画。
每个可见人物每次出场使用独立instance；人物表保留固定外貌标签，instance.prompt写本次可见特征、机位、姿势、表情和动作，局部特写明确hands only、feet only或eye focus。一个槽只写这个人，不把另一人的全套描述也塞进来；共同动作放在该格summary。不要在同一人的提示中用solo否定同格实际存在的另一人。画外音没有人物槽，空镜instances可以为空。
坐标只在JSON元数据中给出：尽量为panel提供与版式设计一致的bounds={x,y,width,height}，是相对全页的近似占位；instance可加center={x,y}，是格内位置。它们用于人物定位，不代表必须把画框画成矩形网格；重叠插格可以占位重叠。没有可用的分镜位置时，程序让图像模型按画面提示自行排位。画面提示要保留版式设计，但不用百分比、精确长宽比或坐标数值。参考框存在时沿用其顺序。人物槽最多22个。
保留用户的画师、角色、配色和数值权重，不猜未提供的作品或画师。protectedVisualPrefix由程序原样前置，无需复制。未提供画风时可用monochrome、greyscale、screentones、lineart；明确彩色时按用户要求。角色与镜头以实际标签为骨架，用自然语言补充关系，不能整页只输出泛泛的散文。
NAI权重是n::内容::，负数是-n::概念::，并不固定为-1。按需要选择强度，例如1.4::overlapping panels::、-3::4koma::、-2.5::static composition::；不要把这些示例当每页必加的词。自由布局可针对方格、重复站姿等设负权重，用户明确要四格或网格时尊重它。UC使用正权重列不想要的内容，程序不再固定追加排除词。保留完整闭合的::分组，不使用(tag:1.2)。不要用排除词误伤用户要求的漫画、多视角、文字或画风。
保留故事的关键镜头和最后的可见收尾。对白放dialogues，不在画面字段重复写引号台词或Text块；程序会添加它们。dialogue默认type="speech"、direction="horizontal"，需要时可用narration/sfx或vertical；画外音可保留speakerId，旁白/sfx用null。无声镜头可省略dialogues，空镜可省略instances。人物之外的编号和顺序由程序生成。每张图的实际文字含分隔符应控制在750字符内。
```

## 四、第二阶段动态替换与追加全文

三个分支互斥。每个分支先替换结构模板中的 `DIALOGUE_SCHEMA`，再在系统提示末尾追加以下对应文字；追加内容前均有一个换行。

### 1. 明确要求无字漫画

条件：预处理结果 `textless=true`。`DIALOGUE_SCHEMA` 替换为空字符串，因此模板中是 `"dialogues":[]`。

```text
用户明确要求无字漫画，用画面叙事，不安排对白、旁白或拟声文字。
```

这里的 `textless` 来自原生提示词输入中没有标题或 `Text:` 台词，同时未加权的逗号分隔标签含 `no text`。普通剧情输入不会由这个预处理分支自动识别为 `textless`，其中的无字要求仍会作为用户素材交给模型。

### 2. 有可引用的原始台词

条件：传入模型的 `sourceTexts` 非空。标题已由程序单独处理，不计入这份台词列表。占位符替换为：

```json
{"sourceId":"s2","speakerId":"c1"}
```

随后追加：

```text
已有原始台词时优先用sourceId引用，程序会取对应原文；也可以直接用text填写台词。尽量保留原文、原语言和故事作用，可以按分镜重排。
```

模板中的 `s2` 只是结构示意，具体可引用编号来自本次 `sourceTexts`。

### 3. 没有可引用的原始台词

条件：前两个分支都不满足。占位符替换为：

```json
{"text":"new words","speakerId":"c1"}
```

随后追加：

```text
没有原始台词编号，用text填写storyDraft中对应语言的台词。
```

### 4. 所有分支共同追加区域数量

以上分支处理后，继续在系统提示末尾追加：

```text
本次生成{区域数}个区域，sections按输入区域顺序返回；在这些图片内讲完故事。
```

`{区域数}` 在实际请求中替换为 `1` 或 `2`，来自规范化后的生成区域数量。

## 五、第二阶段用户消息中的追加指令

第二阶段用户消息沿用第一阶段的 JSON 素材，并增加完整 `storyDraft` 与下方 `formatInstructions`。这段文字位于用户 JSON 字段中，不属于系统提示。

```text
把整页分镜设计明确写进globalPrompt，用英文标签加自然语言描述画框主次、形状、穿插与动线；不要用坐标代替版式描述。panel.summary写具体镜头，instance写该人物这次出场，dialogues保留台词。保留结尾的可见变化；不写精确百分比。
```

用户素材包含输入类型、剧情、风格、人物设定、阅读方向、生成区域与参考框、受保护画面前缀、原始台词、标题和无字标记，并用 `dialogueLanguage` 指明对白语言、`visualLanguage="English"` 指明画面提示语言。程序不把原始 `text` 再重复发送，也不在当前请求中附加固定示例。

## 六、编译与坐标的实际处理

这些是程序执行行为，不是模型提示原文。

- 整页主提示将 `protectedVisualPrefix` 原样放到模型 `globalPrompt` 前方。预处理不删用户版式标签或正负数值权重，编译阶段不再固定追加 `-1::…::` 或固定 UC 排除组。
- 每个可见人物出场保留为一个实例；有文字 `prompt` 的实例才占槽，编译时在实例提示前加入 `panel N, `。每张图保留最多 22 个实例的实际容量边界。
- 台词已有非空 `text` 时沿用模型文字；只有没有文字时才按已知 `sourceId` 取原文。当前不把台词遗漏、重复、改写、画外音未入镜或故事质量作为阻断条件，也不补写缺少的剧情。
- 现有参考框按输入顺序对应分镜，提供边界与人物位置。最终整理时，同格多个人物分布在参考框中部；参考框不等于生成图片中的真实边框或后续裁切模板。
- 没有参考框时，使用模型给出的有效 `bounds`。实例的格内 `center` 会换算为全图坐标；没有有效格内位置时，在该格中部安排人物位置。
- 没有有效分镜边界时，程序不猜等大网格，也不向结果补一个矩形 `bounds`。若该格含人物实例，则整张图的 `section.useCoords=false`；实例的 `(0.5, 0.5)` 只作编辑字段占位，生图关闭自定义人物坐标。无人物的空镜缺少边界，不会单独关闭本区坐标。
- 最终字段整理发现人物 `center` 无效，且该格不属于现有参考框时，也会将 `section.useCoords=false`。前端据此设置 `characterPositionMode="auto"`、`use_coords=false`，让图像模型按画面提示排位。

5–8 格是系统提示中的叙事建议，不是编译器的数量门槛。程序仍要求可解析的 JSON 与可供前端读取的结构，保留模型权限、生成区域尺寸、人物槽和文字容量边界；这些不代表它会验证故事质量。

## 七、前端如何拼接 V5 生图提示

`buildComicAIParams` 默认使用 V5 Full，每次生成一张图，沿用当前区域尺寸。实际拼接顺序如下。

### 整页正面提示

```text
受保护画面前缀 + 模型 globalPrompt
, 质量词后缀
, Panel N[, upper/middle/lower left/center/right area]: 各格 panel.summary
, 未绑定人物的画外音、旁白或拟声描述
Text: 按 order 排列的台词，以两个换行分隔
```

上面是结构示意，实际前三类内容用逗号连接，`Text:` 单独换行；没有对白时不加 `Text:`。默认质量词后缀为：

```text
best quality, amazing quality, very aesthetic, highres
```

有 `bounds` 的分镜根据中心点得到粗略的上/中/下与左/中/右位置；没有 `bounds` 时只加 `Panel N`。每格 `summary` 都进入整页提示，包括没有人物实例的空镜。人物坐标只负责人物定位，具体画框形状、主次、穿插和动线依赖 `globalPrompt` 与 `panel.summary` 的文字描述。

### 人物槽提示

```text
characters 中的人物固定 appearance
, 当前 instance.prompt
, speaking, wide/tall speech bubble with tail pointing to this character
, horizontal/vertical text, "该人物在同格说的台词"
```

只有 `speech` 台词在同格找到相同 `characterId` 的实例时，才绑定到该人物槽；同格有多个匹配实例时绑定第一个。人物槽 UC 使用对应 `instance.negativePrompt`。

未绑定到人物槽的台词进入整页提示：旁白使用 `wide/tall narrator box`，拟声使用 `sound effect`，其余对白使用 `off-screen voice` 和来自画框外的气泡描述。横排使用 `wide`，竖排使用 `tall`，并附文字方向与引号台词。

### 文字与 UC

接收计划和构建请求时，前端清理画面字段中行首 `Text:` 块，以及与已知台词完全相同的带引号文字，避免后续编辑对白时把旧内容再次带入；其他画面标签和权重保留。最终对白仍统一来自 `dialogues`。

整页 UC 使用 `section.negativePrompt`。每图实际文字按 Unicode 字符计数，含空格和双换行分隔符：V5 Full 为 750 字符，Curated 为 374 字符。当前提示与编译器的放宽没有取消这一实际文字容量检查。
