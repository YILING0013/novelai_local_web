# 作品版本与智能图库

本功能使用现有 Next.js / MUI 工作台和 Flask 本地图库，数据仍保存在本机，不需要额外服务、数据库或模型。

## 作品蓝图与分支

- 默认使用普通生成，只保存图片到图库，不自动建立作品或记录作品历史。点击工作台上方的**新建作品**，输入名称后启用作品历史与蓝图，此时保持空作品，第一张生成图片成为 V1。
- 已有首张图片后，**保存提示词版本**保存正负提示词、角色和参数，不调用生成接口，也不消耗 Anlas。
- **作品蓝图**打开蓝图画布，用节点和连线展示图片、提示词及版本父子关系。选择任意节点，点击**从此节点继续**复用其全部已保存参数；下一张图会成为该节点的子版本，原有分支保留。
- **退出作品**保留当前提示词、参数和已有历史，后续生成回到普通图库模式；对旧作品图片使用增强工具也不会自动重新启用作品。需要恢复创作时，通过**打开作品**选择节点并点击**从此节点继续**。
- 启用作品后，连续生成的一批候选从同一个父版本分支；空作品先生成 V1，其余候选从 V1 分支；普通模式下整批都不记录作品历史。生成过程中修改提示词仍沿用原有连续生成行为。
- 图库工具栏可以打开全部作品；图片详情或批量选图后可以将现有图片加入作品。一个图片可以关联多个作品。

生成成功、保存提示词、将现有图片加入版本或执行**恢复为新版本**时，会创建新的版本节点。日常输入提示词不会按每次按键创建节点；可以先完成一轮编辑，再保存为有意义的版本。

蓝图节点按首张图片比例调整大小，完整显示图片。当前创作节点以绿色标记，与蓝色选择状态独立。在蓝图上拖动节点调整位置，平移或缩放画布查看不同分支；框选多个节点可以组成分组。复杂路径和分组可以折叠，暂时不看的节点可以隐藏，随后重新展开或显示。隐藏和折叠只影响画布展示，历史参数与图片快照仍然保留。

桌面端右键节点可继续创作、应用参数、编辑改动说明、成组或隐藏。顶部可以返回作品列表，名称旁可重命名，画布下方可以收起详情。

父子版本通过连线关联，可以在连线上记录这次尝试的思路，例如“保持构图，只提高光照权重”。节点位置、连线备注、分组与可见状态属于可编辑的蓝图数据。调整布局或备注不会改写版本参数、图片快照或真实父子关系。

选择一个图片节点时默认与父级对比，选择两个图片节点时比较这两个节点；纯文本节点直接展示完整参数，不进行对比。可以并排查看图片、打开历史原图，并比较提示词原文、角色和生成参数。原文差异用绿色标出新增内容、红色标出删除内容，权重和参数调整用蓝色区分；原始文本仍可查看。图片输入与遮罩的变化显示摘要，避免将大段编码当成文本展示。

**完整参数**页右侧的**应用所有参数**只更新绘画编辑区，保持原有作品与当前节点；未进入作品时仍保持普通生成模式。**从此节点继续**才会进入该作品并切换后续生成的父节点。

节点的**改动说明**可以编辑，参数快照、图片和父子关系保持不变。

**恢复为新版本**将选中历史的参数与图片快照追加到作品的最新提交之后；不会改写原版本，也不会自动生成图片。需要从旧版本另开分支时使用**从此节点继续**。

历史保存生成时的实际 Seed 与参数。手动提示词版本保留空 Seed 和提示词原文；使用空 Seed 继续生成仍会产生新的随机种子。自动生成的版本保留实际展开后的提示词。

新保存的节点同时保留完整工作台编辑态：角色名称和顺序、临时禁用状态、图生图输入、遮罩、参考图与 Vibe 的原始图片及配置。复用节点时会恢复这些编辑内容，并使用该版本的实际种子和生成参数；暂时禁用的角色或参考仍保持禁用，供后续调整。

旧节点只能复用当时实际保存的数据。如果历史记录缺少原始参考图、Vibe 原图或名称，更新不会自动补回这些信息。需要完整恢复的旧作品，可以重新补齐素材和名称后保存一个新节点，旧历史保持原样。

版本恢复不自动执行 Upscale / Enhance。需要再次使用这些工具时，仍由用户在图像工具中操作。恢复的局部重绘遮罩有明确提示和清除按钮；替换或编辑源图会清除旧遮罩，避免误用。

漫画、图像处理及本地推理的已有图片可以从图库加入作品；启用作品时，普通绘画、图生图、局部重绘和工作台图像增强的生成结果会记录版本。作品历史不等同于漫画文档或图层编辑器的撤销记录。

## 智能图库

参考图库和本地图库仍使用原有入口，支持以下组合条件：

- 标题、文件名或提示词文本搜索；
- 模型、横图 / 竖图 / 方图；
- 必须包含的提示词标签、需要排除的标签；
- 原有虚拟分组与回收站；
- 时间排序，或以选中图片为基准按提示词相似度排序。

图片详情中的**找相似提示词**使用正向、负向及角色提示词的加权 Jaccard 相似度。标签中的空格、下划线、大小写和 NovelAI 权重语法会归一化，画师等标签具有较高权重。它比较提示词，不进行视觉识别，也不调用外部 AI；缺少提示词的图片无法据此判断画面相似。

**动态收藏**保存筛选条件，而不是复制图片。后来生成或导入的图片只要满足条件，就会出现在收藏中。修改搜索、分组或其它条件会退出所选收藏，并以当前界面条件查询。删除收藏只删除这组筛选条件，不影响图片、原分组和版本历史。

## 存储、更新与备份

新增数据仍使用当前 `data_dir`（默认 `nai_flask/data`）：

| 路径 | 内容 |
| --- | --- |
| `image-library.db` | 原图库索引，以及作品、版本、图片关联、蓝图布局、提示词检索缓存和动态收藏 |
| `version-assets/` | 按 SHA-256 去重的不可变历史图片与缩略图 |

原图库图片第一次加入版本时保存一份历史快照；相同内容被其它版本或作品使用时复用该快照。版本中的生成参数与图像输入保存在数据库中，完整工作台编辑态位于参数的 `editor_state` 字段，因此包含大参考图或 Vibe 原图的长期历史会占用额外磁盘空间。

蓝图布局、连线备注、隐藏节点和折叠分组保存在同一个数据库的 `work_blueprints` 表中，每个作品独立保存。该表可以更新，作品版本中的参数快照仍不可变。

图库原图被修改、放入回收站或彻底删除后，已保存的历史快照仍保留。这是版本管理的正常行为；删除原图不再代表所有历史副本都被清除。作品列表支持搜索、多选和批量删除，每次最多 100 个。确认删除作品后，其节点、分支、蓝图及不再被其他作品引用的历史快照会永久移除，图库原图保留；删除当前作品会退出该作品。该操作无法撤销。

更新前先停止本地服务并备份整个当前 `data_dir`，尤其是 **`image-library.db` 与 `version-assets/` 必须一起备份**。已有自定义生成目录仍独立存在，也应按原有方式备份。数据库启动时只增加新表，不搬动原图片，不需要手工迁移。

按原项目方式执行 `setup.bat` 重建后，再用 `start.bat` 启动。若已有对应依赖，也可以在 `next_nai_web` 执行 `npm run build` 后重启本地后端。蓝图与完整编辑态保存不增加部署依赖，也没有新的环境变量、端口或进程要求。

回退到旧代码前停止服务，保留当前数据备份。旧版会忽略新增表与快照目录；重新升级仍可使用这些历史。若需要恢复升级前的全部数据，使用同一备份时点的数据库与数据文件，不要混用不同时间的数据库和快照目录。

生成结果保存成功但历史记录失败时，界面会提示从图库补入作品；不会自动重新生成或重试付费请求。
